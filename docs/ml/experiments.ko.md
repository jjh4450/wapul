# 실험 기록

블럭 분할 모델 실험의 수치 결과입니다. 설계와 판단은 [설계](design.md)에 있고, 여기에는 각 실험의 설정과 숫자를 모읍니다. 새 실험을 하면 표를 추가합니다.

## 공통 설정

- **데이터**: `labels/labels.jsonl` 300건, 모두 사람 검토(`human`). 학습과 채점에 모두 씁니다. 1~8은 검토가 149건이던 때의 기록으로, 채점은 `human` 149건(3,114문장), 학습은 LLM 초안 `auto` 151건까지 썼습니다. 9부터는 300건(6,435문장)입니다.
- **교차 검증**: 풀이 단위 5-fold(`KFold(5, shuffle=True, random_state=0)`). 각 fold의 학습 풀이는 fit 80% / dev 20%로 다시 나눕니다. 임계값, 군집 방식, 조기 종료처럼 고르는 값은 dev로만 정합니다.
- **지표**: 종류는 문장 단위 macro-F1. 블럭 묶기는 B³, CEAF-e, 같은 블럭 쌍 정밀도(P) / 재현율(R) / F1. 따로 적지 않으면 블럭 묶기는 정답 종류를 준 상태에서 logic 문장만 묶은 점수입니다.
- **전체(end to end)**: 예측한 종류로 logic 문장을 고른 뒤 묶은 결과를, input / output / none을 각각 한 묶음으로 보고 매긴 점수입니다. 비 logic 문장이 큰 묶음으로 잡혀 블럭 묶기 점수보다 높게 나옵니다.
- **잡음**: 채점 300건에서 B³ 약 0.018, 종류 F1 약 0.016, 쌍 F1 약 0.040 미만의 차이는 실제 차이로 확정할 수 없습니다(149건에서는 0.026, 0.023, 0.057. 맨 아래 "평가 잡음" 참고).
- **선택 편향**: 9부터의 방식들은 같은 300건의 교차 검증 점수를 보고 골랐습니다. 한 실험 안의 test는 깨끗하지만, 실험 간 비교로 고른 최종 구성의 점수는 조금 낙관적입니다.

고정 방식은 모두 문장 단독과 잡음 기준 안이고, 미세조정은 0.697로 떨어집니다. 미세조정에 쓴 fit 부분은 fold당 약 192개 풀이입니다.

## 15. 대화 분리 방식 블럭 묶기

설정: logic 문장마다 후보 중 하나를 고릅니다(`notebooks/blocks_cv.py`). **문장 단위**는 앞의 logic 문장 전부와 "새 블럭", **블럭 단위**는 지금까지 만든 블럭 전부와 "새 블럭"이 후보입니다. α 같은 임계값이 없습니다. 특징은 SEGMENT 11개 + 바로 앞인지, 거리, 깊이 차이, 대상 문장의 범주·헤더·깊이. 블럭 단위는 블럭 안 문장들과의 특징 최댓값·평균, 블럭 크기, 마지막 문장까지 거리, 가장 최근 블럭인지. MLP는 64칸 은닉층 하나, 30 에폭, softmax로 정답 후보들의 확률 합을 최대화합니다. LightGBM은 LambdaRank(트리 300개, 잎 15개). 앙상블은 두 점수를 후보마다 softmax 확률로 바꿔 평균합니다.

| 후보 | 점수기 | B³ | CEAF-e | 쌍 P | 쌍 R | 쌍 F1 |
|------|--------|----|--------|------|------|-------|
| 쌍 + α 군집 (12, 비교 기준) | RBF SVM | 0.793 | 0.692 | 0.564 | 0.712 | 0.630 |
| 문장 단위 | MLP (시드 5개) | 0.812 ± 0.003 | 0.720 ± 0.002 | 0.589 | 0.712 | 0.644 ± 0.004 |
| | MLP + 상대 특징 (시드 5개) | 0.810 ± 0.002 | 0.711 | 0.575 | 0.713 | 0.636 |
| | LightGBM | 0.810 | 0.707 | 0.574 | 0.739 | 0.646 |
| | LightGBM + 상대 특징 | 0.811 | 0.705 | 0.572 | 0.737 | 0.644 |
| | RBF SVM + 클래스 가중치 | 0.783 | 0.659 | 0.524 | 0.711 | 0.604 |
| | RBF SVM | 0.758 | 0.627 | 0.449 | 0.763 | 0.565 |
| | CodeBERT 쌍 인코더, dev 조기 종료 | 0.799 | 0.687 | 0.533 | 0.724 | 0.614 |
| 블럭 단위 | LightGBM | 0.809 | 0.732 | 0.654 | 0.682 | 0.668 |
| | LightGBM + "새 블럭" 보정값 (dev 쌍 F1) | 0.803 | 0.720 | 0.602 | 0.719 | 0.655 |
| | MLP (시드 5개) | 0.813 ± 0.002 | 0.739 ± 0.003 | 0.666 | 0.683 | 0.674 ± 0.004 |
| | **MLP + LightGBM 앙상블 (시드 5개)** | **0.816 ± 0.002** | **0.742 ± 0.004** | 0.664 | 0.692 | **0.678 ± 0.006** |

- 같은 AST 특징으로 "후보 중 고르기" 형식을 쓰면 쌍 + α 군집보다 B³가 약 0.02 오릅니다(MLP, LightGBM). 후보를 하나씩 따로 학습한 RBF SVM은 이 형식에서 0.758~0.783으로, 쌍 + α 군집(0.793)을 넘지 못합니다. 학습 방식과 모델 종류가 함께 달라 어느 쪽 효과인지는 가르지 않았습니다.
- 상대 특징("그 관계를 가진 후보 중 가장 가까운가")은 효과가 없습니다.
- 블럭 단위로 바꾸면 B³는 비슷하고 정밀도, CEAF-e, 쌍 F1이 오릅니다. 보정값은 재현율을 되찾지만 CEAF-e와 쌍 F1을 잃어 쓰지 않습니다.
- CodeBERT 쌍 인코더(후보마다 "후보 문장 + SEGMENT 사실 + 대상 문장 맥락", 128 토큰)는 AST MLP보다 높지 않고 CPU 비용이 커서(16) 쓰지 않습니다.
