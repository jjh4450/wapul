# 설계

블럭 분할 모델의 설계와 근거가 된 연구입니다. 구성 요소를 바꾸거나 더할 때 이 문서의 상태 표와 결과 표를 함께 고칩니다.

## 서비스가 정한 조건

기획서(`data/docs/`의 PS 공부 기록 사이트 기획서)에서 모델에 걸리는 조건입니다.

- **출력은 종류와 "로직 n"까지입니다.** 블럭 이름은 만들지 않습니다.
- **애매하면 더 잘게 나눕니다.** 질문이 빠지는 손실이 질문이 하나 더 붙는 손실보다 크고, 핵심 연산이 둘이면 나눕니다. 그래서 두 블럭을 잘못 합치는 실수를 잘못 나누는 실수보다 무겁게 봅니다.
- **완벽한 분할이 목표가 아닙니다.** 사용자가 블럭을 고칠 수 있고, 자동 분할이 사람 합의와 같았던 비율은 69%였습니다(Tao & Kim 2015).
- **작은 모델로 빠르게 돕니다.** 줄마다 주변을 보고 분류하는 작은 모델(CodeSeg 방식)이 기획서가 정한 방향입니다.
- 경계 질문(조건, 비교)과 구조 질문(재귀, 반복)을 붙일 블럭은 모델이 아니라 정적 분석이 고릅니다. `ast_features.py`의 AST 정보를 함께 쓸 수 있습니다.

## 문제를 두 개의 알려진 문제로 본다

| 우리 단계 | 같은 구조의 문제 | 이유 |
|-----------|------------------|------|
| 종류 분류 | 적은 라벨로 하는 텍스트 분류 | 문장마다 4개 중 하나, 라벨은 풀이 300건 |
| 블럭 묶기 | 상호참조 해결(coreference) | 앞에서부터 읽으며 "기존 묶음에 붙일지, 새로 열지"를 정하고, 묶음이 떨어져 있을 수 있음 |

검토된 풀이의 약 43%에 떨어진 로직 블럭이 있습니다. 그래서 이어진 구간의 경계만 찍는 텍스트 분할 방식은 쓰지 않습니다.

## 구성 요소와 상태

| 구성 요소 | 근거 | 상태 |
|-----------|------|------|
| 정규화 + tree-sitter 문장 단위 | 라벨이 이 단위로 만들어짐 | 적용 (`normalize.py`, `units.py`) |
| 앞뒤 K문장 맥락을 붙인 입력 | CodeSeg | 적용 (`context_text`, K=3). 논문은 인코더를 미세조정, 여기서는 고정 임베딩 |
| 고정 임베딩 + 로지스틱 회귀 | SetFit의 linear probe 기준선 | 적용 (E5-base-v2, 모델 비교는 아래 결과) |
| 문장 쌍 "같은 블럭?" 분류 + 순서대로 붙이기 | 상호참조 해결 | 적용: 쌍 확률을 블럭 단위로 모아(최대, 평균, 마지막 문장, 블럭 크기, 거리, 블럭 평균 임베딩) 두 번째 분류기로 점수를 매김. 비교용 closest-first도 함께 평가 |
| 임계값 α 고르기 | 서비스 조건 "애매하면 나눈다" | 학습 fold를 fit / dev로 나눠, dev에서 같은 블럭 쌍 F0.5(정밀도 2배 가중)가 가장 높은 α. 테스트 점수는 쓰지 않음 |
| 블럭 규칙 특징 (데이터 흐름 사슬, 제어문 덩어리, 같은 문법 유형) | SEGMENT | 적용 (`ast_features.py`): tree-sitter로 쓰는 변수·읽는 변수, 감싸는 반복문·분기·함수, 형제 여부, 문장 범주 |
| 종류 분류용 AST 특징 | — | 적용: 문장 범주, 헤더 여부, 깊이, 입출력 식별자 |
| 같은 블럭 / 다른 블럭 쌍으로 임베딩 대조 학습 | SetFit | 구현 (`contrastive.py`, `baseline --setfit`). 라벨을 쓰므로 fold마다 fit 부분으로만 학습. 종류 분류는 나아지고 블럭 묶기는 조금 나빠짐(아래 결과) |
| 라벨 없는 corpus로 임베딩 도메인 적응 | TSDAE | 검토 후 제외. 단독으로는 종류 분류가 나빠지고, SetFit의 출발점으로도 차이가 잡음 수준 (`tsdae.py`는 남겨 둠) |
| 스코프를 구분한 def-use 연결 (가장 최근 정의 → 사용) | SEGMENT의 데이터 흐름 사슬 | 미적용. 지금은 변수를 이름으로만 비교해서 반복문마다 다시 쓰는 `i`, `j`가 같은 변수로 잡힘 |
| 의사 라벨 자기 학습 | self-training 연구 | 미적용, 후순위 |
| 평가: B³, CEAF-e | 상호참조 평가 | 적용 (`metrics.py`) |

## 현재 결과

판단에 쓰는 요약입니다. 실험별 설정과 전체 수치는 [실험 기록](experiments.md)에 있습니다.

사람이 검토한 풀이 149건(3,114문장)에 대한 5-fold 교차 검증입니다. 블럭 묶기는 정답 종류를 준 상태에서 logic 문장만 묶은 점수입니다. 평가 풀이가 적어서 0.01 안팎의 차이는 잡음일 수 있습니다.

**현재 구성** (E5-base-v2 고정 임베딩, AST 특징, 블럭 단위 점수, dev F0.5로 α 선택)

| 대상 | 점수 |
|------|------|
| 종류 macro-F1 | 0.888 (input 0.889, output 0.795, logic 0.923, none 0.946) |
| 블럭 묶기 B³ / CEAF-e | 0.780 / 0.658 |
| 같은 블럭 쌍 정밀도 / 재현율 | 0.701 / 0.531 |
| 비교 기준: 문장마다 따로 / 전부 한 블럭 | B³ 0.495 / 0.511 |

- 가장 약한 종류는 output입니다. 출력문의 약 28%를 logic으로 봅니다.
- α는 모든 fold에서 0.7 근처로 골라집니다. 이때 블럭이 정답보다 약 1.26배 많이 나옵니다.

**임베딩 모델 비교** (나머지 구성은 같음)

| 모델 | 종류 macro-F1 | 블럭 묶기 B³ | 같은 블럭 쌍 F1 |
|------|---------------|--------------|-----------------|
| E5-base-v2 (범용 텍스트) | 0.888 | **0.780** | **0.604** |
| UniXcoder (코드) | **0.896** | 0.767 | 0.575 |
| CodeT5+ 110M embedding (코드, C++ 포함) | 0.892 | 0.776 | 0.595 |

차이가 작고, 블럭 묶기에서 앞선 E5를 기본 모델로 씁니다. E5는 BERT 계열이라 TSDAE를 그대로 적용할 수 있습니다. `jinaai/jina-embeddings-v2-base-code`는 동봉 코드가 지금 transformers에서 돌지 않아 비교하지 못했습니다. CodeT5+도 동봉 코드가 돌지 않아, `baseline.py`가 표준 T5 인코더에 같은 가중치를 올려 씁니다.

**TSDAE 도메인 적응** (E5 위에, 지도 학습 없이 바로 분류기)

| 임베딩 | 종류 macro-F1 | 블럭 묶기 B³ | 같은 블럭 쌍 F1 |
|--------|---------------|--------------|-----------------|
| E5-base-v2 | **0.888** | **0.780** | **0.604** |
| E5-base-v2 + TSDAE | 0.869 | 0.776 | 0.596 |

종류 분류가 떨어지고(input 0.889 → 0.847) 블럭 묶기는 잡음 수준 차이입니다. 대조 학습된 E5의 임베딩 공간을 복원 학습이 흐트러뜨린 것으로 보입니다. 논문에서 효과가 확인된 설정은 사전학습만 된 모델에서 출발해 TSDAE 뒤에 지도 학습을 하는 것입니다.

**SetFit식 대조 학습** (fold마다 fit 부분으로 미세조정)

| 임베딩 | 종류 macro-F1 | output F1 | 블럭 묶기 B³ | 같은 블럭 쌍 F1 | 전체 B³ |
|--------|---------------|-----------|--------------|-----------------|---------|
| E5-base-v2 | 0.888 | 0.795 | **0.780** | **0.604** | 0.817 |
| E5-base-v2 + SetFit | 0.905 | 0.818 | 0.767 | 0.580 | 0.825 |
| E5-base-v2 + TSDAE + SetFit | **0.910** | **0.840** | 0.766 | 0.586 | **0.827** |

- 종류 분류는 약 0.02 오릅니다.
- 블럭 묶기는 조금 떨어집니다. 학습 쌍의 다수인 종류 쌍이 logic 문장끼리를 가깝게 당겨서, logic 문장 사이를 가르는 데 불리해진 것으로 보입니다.
- TSDAE를 앞에 붙인 차이는 잡음 수준이라 TSDAE는 쓰지 않습니다.

학습 설정: 배치 32, 최대 길이 224, 1 에폭, 학습률 3e-5. 최대 길이 256은 16GB GPU에서 약 2GB가 넘쳐 공유 메모리로 내려가면서 크게 느려졌습니다.

**라벨 수에 따른 효과** (`learning_curve.py`, E5 원본 구성)

| fold당 학습 풀이 | 종류 macro-F1 | 블럭 묶기 B³ | 같은 블럭 쌍 F1 |
|------------------|---------------|--------------|-----------------|
| 60 | 0.864 | 0.751 | 0.551 |
| 120 | 0.878 | 0.772 | 0.594 |
| 180 | 0.881 | 0.773 | 0.596 |
| 240 | 0.888 | 0.780 | 0.604 |

곡선에 맞춘 외삽으로는 1,600건에서도 블럭 묶기 B³ 0.783, 종류 0.904 정도입니다. 지금 모델(고정 임베딩 + 선형 분류기)이 포화된 것이라, 블럭 묶기는 라벨 수보다 특징과 모델을 고치는 쪽이 먼저입니다.

**평가 잡음** (채점 풀이를 부트스트랩)

| 채점 풀이 수 | 실제 차이로 볼 수 있는 크기: B³ | 종류 F1 | 쌍 F1 |
|--------------|-------------------------------|---------|-------|
| 149 | 0.026 | 0.023 | 0.057 |
| 300 | 0.018 | 0.016 | 0.040 |
| 600 | 0.013 | 0.012 | 0.029 |
| 1,000 | 0.010 | 0.009 | 0.022 |

독립된 두 실행을 비교한다고 본 보수적인 값이고, 같은 평가셋에서 비교하면 실제 기준은 조금 더 작습니다. 이 문서의 0.01 안팎 차이는 확정할 수 없는 차이입니다. 채점 풀이를 늘리는 가장 싼 방법은 `auto` 초안 151건을 검토해 `human`으로 바꾸는 것입니다.

**α에 따른 합치기 / 나누기** (`baseline --sweep`, 분석용으로 테스트에서 α마다 잰 값)

| α | 블럭 수 (정답 대비) | B³ | 쌍 정밀도 | 쌍 재현율 |
|---|---|---|---|---|
| 0.5 | 0.89배 | 0.773 | 0.535 | 0.709 |
| 0.6 | 1.05배 | 0.787 | 0.611 | 0.642 |
| 0.7 | 1.26배 | 0.784 | 0.697 | 0.548 |
| 0.8 | 1.68배 | 0.730 | 0.806 | 0.367 |

B³는 0.55~0.7에서 거의 평평하고, 이 구간에서는 나누는 쪽으로 기울여도 점수 손해가 거의 없습니다. 0.75를 넘으면 블럭이 빠르게 잘게 쪼개집니다.

## 근거

**CodeSeg** — 코드를 기능 단위 블럭으로 나누는 가장 가까운 선행 연구. 줄마다 앞뒤 줄을 맥락으로 붙여 분류하는 방식이 범위를 통째로 뽑는 방식보다 나았고, 미세조정한 CodeBERT·CodeT5+가 LLM보다 정확하고 100~170배 빨랐습니다. 다만 같은 범주가 연속된 줄을 묶을 뿐이라 떨어진 블럭은 다루지 않습니다. 우리 종류 분류에 해당합니다.
[논문](https://dl.acm.org/doi/10.1145/3820755.3821483) · [코드](https://github.com/Dahouabdelhalim/CodeSeg)

**상호참조 해결의 점진적 군집** — 문서를 앞에서부터 읽으며 각 표현을 기존 군집들과 비교해 붙이고, 모든 점수가 임계값 α보다 낮으면 새 군집을 엽니다. 군집 표현은 붙을 때마다 갱신합니다. 우리 블럭 묶기와 같은 구조입니다.
[Xia 외 2020](https://aclanthology.org/2020.emnlp-main.695/) · [Grenander 외 2022](https://aclanthology.org/2022.emnlp-main.28/)

**SetFit** — 임베딩 모델을 "같은 클래스 쌍은 가깝게, 다른 클래스 쌍은 멀게" 대조 학습한 뒤 로지스틱 회귀를 얹습니다. 클래스당 8개로도 전체 데이터 미세조정에 근접했습니다. 블럭 묶기에서는 같은 블럭 / 다른 블럭 쌍을 그대로 학습 쌍으로 씁니다.
[논문](https://arxiv.org/abs/2209.11055)

**TSDAE** — 라벨 없는 도메인 텍스트로 임베딩을 적응시키는 방법 중 MLM, SimCSE, CT보다 일관되게 좋았습니다. 약 1만 문장에서 효과가 포화되고, "도메인 비지도 학습 → 지도 학습" 순서가 반대보다 낫습니다.
[TSDAE](https://aclanthology.org/2021.findings-emnlp.59/) · [GPL (도메인 적응 비교)](https://arxiv.org/abs/2112.07577)

**SEGMENT** — 메서드 코드를 "의미 있는 블럭"으로 나누는 규칙 기반 도구. 블럭을 데이터 흐름 사슬, 제어문 덩어리, 같은 문법 유형의 연속으로 보고 강도를 이 순서로 둡니다. 쌍 분류기의 구조 특징으로 씁니다.
[Wang 외 2011](https://pdfs.semanticscholar.org/eae0/a9d1a3df1be559af97a8885056a8b85300c5.pdf)

**임베딩 모델 선택** — 코드 검색 벤치마크 CoIR에서 일반 텍스트 모델 E5-base(1.1억)가 코드 전용 UniXcoder(1.23억)보다 높았습니다. 코드 전용 모델로 한정하지 않고 우리 데이터에서 직접 비교해 고릅니다.
[CoIR](https://arxiv.org/abs/2407.02883)

**평가 지표** — B³와 CEAF는 상호참조 평가의 표준입니다. MUC는 한 원소짜리 군집을 무시하고 군집을 적게 만들수록 유리하며, 단순 Rand 지수는 1 근처로 몰려 차이를 잘 보여 주지 못합니다.
[Cai & Strube 2010](https://aclanthology.org/W10-4305.pdf) · [BLANC](https://www.cs.cmu.edu/~hovy/papers/10BLANC-coref-metric.pdf)

**자기 학습** — 반복할수록 잘못된 의사 라벨이 쌓이는 문제(semantic drift)가 알려져 있습니다. 쓰려면 높은 임계값, 한 번에 더하는 양 제한, 검증셋으로 멈출 시점 정하기가 필요합니다. 비교 실험에서는 사전학습의 기여가 더 컸습니다.
[Karisani 2023](https://aclanthology.org/2023.findings-acl.769.pdf)

## 순서

각 단계는 같은 평가로 이전 단계와 비교해, 실제로 도움이 된 것만 남깁니다.

블럭 묶기에서 문장별 임베딩을 빼도 점수가 잡음 안에서 같습니다([실험 기록 8](experiments.md)). 블럭 소속은 두 문장 사이의 관계라서, 따로 임베딩한 두 벡터를 비교해서는 잘 드러나지 않습니다. 그래서 블럭 묶기는 관계를 직접 다루는 쪽으로 갑니다.

1. 스코프를 구분한 def-use 쌍 특징: 지금 정보가 나오는 AST 관계 특징을 보강
2. 두 문장을 맥락과 함께 한 번에 읽는 작은 cross-encoder로 "같은 블럭?" 판단
3. 군집 오라클 확인: 쌍 확률 대신 정답 쌍을 넣어 디코더의 상한을 재고, 디코더가 병목일 때만 군집 방식을 더 다룹니다
4. 필요하면 문장 임베딩 위 BiLSTM, 자기 학습

종류 분류는 임베딩이 기여하므로 SetFit으로 미세조정한 모델을 씁니다.

추론은 CPU를 목표로 합니다. 학습은 GPU에서 하고, 서비스에서는 임베딩 모델 한 번 통과와 scikit-learn 분류기만 돌립니다. cross-encoder를 쓰면 풀이마다 logic 문장 쌍 수만큼 모델을 통과하므로 CPU 시간을 따로 재야 합니다.
